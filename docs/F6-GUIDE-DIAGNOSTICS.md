# F6 输入预览与诊断

## 每帧细节保留调试

在“多帧 NR 复用”页点击 **打开每帧细节保留调试**，或使用原输入预览条旁的同名按钮。独立窗口记录最近 120 个真实源帧：当前深度/运动、工作尺寸、实际缩放与相位、读取的历史源、源时间差、准入、录制、实际提交、GPU 完成和 recording Reset。可冻结帧记录阅读；列表不代替像素贡献证明。

窗口中的调试图单选 **关闭／实际贡献／拒绝原因／历史年龄／重投影出生颜色／当前 NR／融合结果／最终稳定权重**。沿用原有清晰的全屏 GPU 预览，不另做低清画布。拒绝图：绿=模型域非零增量；蓝=当前细节更强或无增量；灰=无相邻历史；黄=过期；橙=深度；紫=运动；红=越界；青=出生颜色/结构；暗红=无效输入。年龄图绿→红代表从新到接近最长寿命。 混合 RGB 的新旧原始残差共用最老搬运年龄，因此新通道可能提前衰减，但旧通道不会被重新计龄续命。像素图复用同一生产 evaluator、同一当前/上一源帧，只写显示用纹理，不会写回历史。 子视图与快照 revision 在预约时一并固定，切图时不会把旧图当成新图。诊断使用独立三个 descriptor/常量槽；忙时只跳过诊断，不消耗 NR 生产槽位。

**每帧**指每个真实 NR 源帧的状态记录；GPU 图像最多 30 Hz，忙时跳过，窗口显示实际图像的源帧与年龄。贡献比例另用最多 2 Hz 的异步读回，明确其源帧和年龄，不冒充每帧统计。调试窗关闭/隐藏后账本和贡献读回需求停止；普通设置页不会启动读回。全屏预览按原规则在菜单关闭后继续，选择“关闭”才停。NR/持续保留关闭或输入不可用时，历史保持不可用，不用旧画面证明当前正常。

## 每源帧持续保留与最终稳定调节

“细节持续保留（每源帧完整计算）”开启后，直接使用下方的**持续保留：深度容差／颜色容差／运动容差**。这些是独立配置并实际进入生产历史 shader；旧“搬运采样的可信范围”只属于间隔复用。深度是相对差，1 忽略有效像素间的深度差；颜色是模型输入域原画与出生颜色的差，默认 0.08；运动是局部中心运动场曲率的工作像素容差，默认 2 px。较高值减少拒绝，也可能放进错误表面的细节。调参会切换历史身份，旧配置不能继续贡献。

**最终历史稳定时间**为 0～2000 ms，0 关闭。它是 NR 残差平均的衰减时间常数和平均滞后上限，并非强制显示某张旧整帧，也不是精确截断的时间窗。可先试 100～250 ms，低可信比例 0.65、稳定变化容差 0.08。低可信比例大于 0 时，坏深度或坏运动仍允许受控降噪；运动无效或越界时退到当前屏幕位置的 NR 残差，并用当前原画外观与逐通道修正上限约束。1 完全取消像素 guides 信任对稳定权重的削弱，0 恢复相应否决。显露的新表面、切场景、身份/编码改变、非相邻源、未完成或无效资源仍不会借旧画面恢复。长时保留时长/强度为 0 时，短时稳定仍可独立使用，但总开关须开启。

稳定在同一次 mode24 调度中执行，单独保存两张模型分辨率 FP16 残差/平均滞后纹理，关闭时不分配；沿原 queue/fence/Reset 退休链，不扩池或加 CPU 等待。游戏原画总取当前帧；稳定值不回写模型或长时原始残差/出生指纹。它能抑制 NR 正负噪声与照明跳变，但提高时长、低可信比例或变化容差会增加拖尾风险，需按游戏实测。

独立调试窗展开**调节历史参数（与 NR 设置同步）**即可调整同一组值，并显示每个源帧实际采用的阈值。图像新增**最终稳定权重**；拒绝图的黄绿色表示低 guides 可信度下稳定实际产生了非零贡献。调试窗口关闭后停止其读回；普通 NR 设置页不会主动请求读回。

## 原有预览与离线采集

在 NR 设置底部原有的“输入资源预览”条单选：**关闭／NR 编码前颜色／NR 输入颜色／NR 深度／NR 运动／FG 颜色／FG 深度／FG 运动／历史贡献**。

选择后等比全屏显示有效区域的 GPU 快照，菜单叠在上面。关闭菜单继续预览；选择“关闭”停止新增采样。冻结保留最后完成的快照，并标明源帧、代次和年龄。每个新源帧最多采样一次，上限 30 Hz；忙时跳过。当前独立预览支持 DX12 DIRECT recording 与 SDR 输入／输出；其它后端或 HDR 明确不可用，不回退放大 CPU 格子图。

“原始资源”“仅预览上下翻转”和“显示增益”只改变显示。FG 来自本帧成功 tag 的实际纹理、rect 和 SDK 运动缩放，NR 关闭仍可采样。NR 预览不覆盖正常模型输出；FG 开启时在 SDK 输入封存后的物理输出层显示。资源需所属 queue/fence 完成及本次 recording 成功 Reset，延迟回执携带显式执行代次。预览副本不作为算法输入、准入或退休证明。

诊断详情分别保留 NR 模型、历史反馈与 FG 的收到／拒绝／录制／提交／GPU 完成、字段来源、最近完成及年龄。历史贡献显示同帧融合结果与 fresh NR 的 RGB 差值；未测量则保持未知，不能把录制融合当成非零贡献。无 HUD 分离输入时 FG 继续运行，UI 未保护；本轮不以 HUD 稳定为门槛。

贴图上下翻转、运动 Y 取反和深度近远约定是独立概念。没有转头校准向导，也不自动更改 NR／FG 方向、缩放或画质设置。

展开“预览详情／离线双帧”，可异步导出同代次的两张连续真实源帧及对应 guides；仅该显式请求使用缩小 CPU 读回。最多等 15 秒，缺失／不连续明确失败。JSON 写入当前 DLL 旁的 diagnostics 目录，记录 PID、磁盘候选 SHA256、快照、配置及有界事件；loaded-memory SHA 未核就保持未知。离线八组合比较，不写游戏配置：

~~~powershell
python tools/runtime/Analyze-F6GuidePair.py <pair.json> --output <report.json>
~~~

“临时只看生成帧”使用 SDK 已有显示选项，与输入预览互斥；关闭菜单恢复，不改变倍率，不补造生成帧身份。

FPS overlay 分别报告真实 Evaluate 源频率、SDK 查询区间呈现计数和“实际显示率未知”。请求倍率、菜单回调和录像编码帧率不代表显示率。使用已有 PresentMon 采集真实显示事件：

~~~powershell
pwsh -File tools/runtime/Collect-F6DisplayTiming.ps1 -TargetPid <PID> -PresentMonPath <PresentMon.exe>
~~~

原神按 SR、SR＋NR、SR＋FG、SR＋NR＋FG 分段验收；固定场景、分辨率和参数，各预热 5 秒、采集 30 秒。用户已将本轮残影／闪回定位到 NR 细节保持，重点复测 1 秒历史栅栏与调参后持续掉速，FG 独立测试仍保留。检查人物／物体残影、旧帧闪回、遮挡、热调节无需切窗、预览开销和真实显示节奏。星铁、ZZZ 各自回归；CPU/WARP、构建、部署、实际加载、画面和性能分别记录。
